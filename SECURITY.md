# Безопасность macros

Сайт представляет собой статические HTML, CSS и JavaScript на GitHub Pages. Серверного приложения, базы данных, форм входа и загрузки файлов в этом репозитории нет. Это сокращает поверхность атаки, но не означает полной неуязвимости.

## Что настроено в коде

- Content Security Policy в начале каждого HTML: скрипты, стили, шрифты и изображения загружаются только с текущего источника. Встроенные скрипты и обработчики событий, внешние подключения JavaScript, формы, фреймы, плагины и workers запрещены.
- Trusted Types запрещает небезопасную вставку HTML и кода в браузерах, которые поддерживают эту возможность. В остальных браузерах продолжают работать остальные правила CSP.
- SHA-384 Subresource Integrity проверяет JavaScript и CSS перед использованием. Если файл изменён без обновления HTML, браузер откажется его применять. Если атакующий изменит и HTML, и контрольные суммы, эта мера его не остановит.
- Старые адреса используют отдельный локальный скрипт перенаправления. Адрес назначения фиксирован внутри сайта, допустимые якоря перечислены явно.
- Referrer Policy `no-referrer` и `rel="noopener noreferrer"` у внешних ссылок ограничивают передачу адреса исходной страницы и доступ нового окна к ней.
- GitHub Actions проверяет политику, контрольные суммы и распространённые ошибки публикации. Задание имеет только `contents: read`; checkout закреплён полным SHA, сохранение учётных данных отключено.

Проверка CI не является полноценным аудитом или пентестом. Она не делает проверку обязательной перед публикацией: для этого владелец должен отдельно настроить правила защищённой ветки.

## DDoS и ограничения GitHub Pages

У сайта сейчас только адрес `macro-vibe.github.io`. Домены `github.io`, TLS и инфраструктуру доставки контролирует GitHub. Собственный WAF, сетевую фильтрацию, управляемое ограничение запросов и Cloudflare для этого чужого домена из репозитория настроить нельзя. Здесь не установлены и не заявлены такие средства.

Устойчивость к сетевым атакам сейчас зависит от инфраструктуры GitHub Pages/CDN и правил сервиса. При большой нагрузке возможны ограничения доступности. JavaScript, CAPTCHA на статической странице и скрытые ссылки не заменяют защиту хостинга. Нагрузочные или DDoS-тесты публичного сайта не выполнялись.

Для дополнительной управляемой защиты нужен собственный домен и доступ к его DNS/Cloudflare. После подключения можно настроить проксирование, доступные на выбранном тарифе правила WAF и ограничения запросов. HTTPS между Cloudflare и GitHub Pages должен быть настроен корректно, с проверкой сертификата. Даже такая настройка не гарантирует постоянную доступность при любой атаке.

GitHub Pages не позволяет этому репозиторию задавать произвольные HTTP-заголовки. CSP через meta работает, но `frame-ancestors` (защита от встраивания чужими сайтами) требует именно HTTP-заголовка. Файлы `_headers` и `.htaccess` на GitHub Pages эту задачу не решают. Управляемые заголовки можно добавить на подходящем хостинге или собственном прокси после подключения домена.

## Защита доступа к исходникам

Защита аккаунта GitHub важна не меньше кода: включите двухфакторную аутентификацию или passkey, сохраните коды восстановления отдельно и выдавайте токенам только необходимые права. При совместной работе настройте защиту ветки `main` и обязательное прохождение проверок. Эти настройки аккаунта и репозитория здесь автоматически не менялись.

Не загружайте в репозиторий `.env`, токены, приватные ключи, Telegram-сессии или tdata. Локальная проверка замечает некоторые распространённые форматы, но не заменяет полноценное сканирование секретов.

## Проверка и дальнейшие изменения

```sh
python3 tools/check_security.py
node --check assets/site.js
node --check assets/redirect.js
```

При изменении CSS или JavaScript нужно обновить и `?v=` (первые 12 символов SHA-256), и `integrity` (SHA-384 в base64) во всех HTML, которые используют этот файл. Иначе браузер намеренно заблокирует изменённый ресурс. Не ослабляйте CSP через `unsafe-inline` или `unsafe-eval` ради нового виджета — сначала проверьте его требования.

В браузере проверьте нормальную работу сайта и отсутствие неожиданных нарушений CSP. Проверки локально подтвердили работу карусели, прокрутки и старых ссылок, а также блокировку пробных вставок кода, внешних запросов и файлов с изменённой контрольной суммой.
